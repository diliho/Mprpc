## 1. 阶段四交付物

### 1.1 分布式能力升级

#### 多 Provider ZooKeeper 注册（顺序临时子节点）

将 ZK 注册从单一 znode 覆写改为标准 ZooKeeper 顺序临时子节点模式，支持多 Provider 并存：

| 特性 | 实现 |
|------|------|
| 注册模式 | `ZOO_EPHEMERAL \| ZOO_SEQUENCE` 顺序临时子节点 |
| 节点路径 | `/ServiceName/MethodName/inst_0000000000` |
| 多 Provider | 每个 Provider 创建独立子节点，共存于同一方法路径下 |
| 消费端发现 | `zoo_wget_children()` 列出所有子节点 + 随机选择负载均衡 |
| ZK Watcher | `zoo_wget_children()` 注册子节点变更 watcher，实时感知上下线 |
| 后向兼容 | `GetChildren()` 为空时自动回退 `GetData()` 读取旧格式 |
| 优雅关闭 | Provider shutdown handler 删除所有已注册的临时子节点 |

修改文件：
- `src/mprpcprovider.cc`：注册逻辑改为 `Create()` with `ZOO_SEQUENCE`，新增 `m_registered_znodes` 跟踪
- `src/include/mprpcprovider.h`：新增 `getRegisteredZnodes()` 访问器
- `src/zookeeperutil.cc`：`Create()` 支持 output 参数返回完整路径
- `src/mprpcchannel.cc`：`discoverService()` 改用 `GetChildren()` + 随机选择 + child watcher

#### Consumer 端缓存与降级

- 三级降级策略：ZK children → ZK GetData（旧格式）→ 本地缓存（30s TTL）
- ZK 宕机时自动降级到缓存地址，ZK 恢复后自动重新发现
- 指数退避重试（最多 3 次，`1000ms << i` + 随机抖动）

#### Consumer 端直连模式

新增 `MprpcChannel::setDirectAddress()` 方法，支持绕过 ZK 直连指定 Provider：
- 用于性能基准测试和单 Provider 调试
- `discoverService()` 检测到直连地址后立即返回，跳过所有 ZK/缓存逻辑

### 1.2 故障转移与自愈验证

#### Provider 故障转移

| 测试场景 | 结果 |
|----------|------|
| 杀掉 Provider-1 | Provider-2/3 继续服务，100% 成功率 |
| ZK 自动清理临时节点 | 5 秒内 inst_0000000000 自动删除 |
| 消费端自动切换 | ZK watcher 触发缓存失效，下次调用随机选择存活节点 |

#### Provider 自愈（重新注册）

| 测试场景 | 结果 |
|----------|------|
| 重启 Provider-1 | 自动重新注册 inst_0000000003（顺序号递增） |
| 消费端感知 | 3 个 Provider 全部恢复服务 |
| 数据正确性 | inst_0000000003 → `0.0.0.0:8001`，验证正确 |

#### ZooKeeper 故障转移

| 测试场景 | 结果 |
|----------|------|
| 停止 ZooKeeper | 消费端从缓存继续服务，0% 错误率 |
| QPS 保持 | 14,164 QPS（ZK 正常时 15,791 QPS，仅下降 10%） |
| 重启 ZooKeeper | Provider 自动重连，消费端恢复 ZK 发现 |

## 2. Docker Compose 部署（10 容器，host 网络）

### 架构

所有容器使用 `network_mode: host`（podman 3.4.4 CNI 不兼容 1.0.0 格式）：

| 服务 | 容器名 | 端口 | 说明 |
|------|--------|------|------|
| MySQL | deploy_mysql_1 | 3306 | 状态存储，健康检查 |
| ZooKeeper | deploy_zookeeper_1 | 2181 | 服务注册发现，健康检查 |
| Redis | deploy_redis_1 | 6379 | 缓存，健康检查 |
| Control Plane | deploy_controlplane_1 | 8080 | 管控面 API |
| AlertManager | deploy_alertmanager_1 | 9093/9094 | 告警管理 |
| Prometheus | deploy_prometheus_1 | 9090 | 指标采集（5 个 target） |
| Grafana | deploy_grafana_1 | 3000 | 监控可视化 |
| Provider-1 | deploy_provider-1_1 | 8001(RPC)/9091(metrics) | RPC 服务节点 |
| Provider-2 | deploy_provider-2_1 | 8002(RPC)/9092(metrics) | RPC 服务节点 |
| Provider-3 | deploy_provider-3_1 | 8003(RPC)/9095(metrics) | RPC 服务节点 |

### 关键配置

- Provider-3 metrics 端口使用 9095（AlertManager 绑定了 9093/9094）
- ZooKeeper 健康检查使用 `srvr` 命令（`ruok` 未在 4 字母白名单中）
- Prometheus 抓取配置：`127.0.0.1:9091/9092/9095`
